# 设置窗口与数据备份

## 这里有什么

以页面内窗口形式打开的设置面板，也是绝大多数设置的写入方。分区：通用、外观、Dock、数据、关于、更新日志。

「数据」分区里除了导出、导入、WebDAV 配置，还直接嵌了快速链接的管理界面。

## 控件与行

内容由声明式 builder 生成，每行一个 `type`：`toggle` / `select` / `slider` 各是一个控件，`custom` 交出自己的一段 HTML 与绑定函数。

`chips` 是第五种：一行装几个彼此独立的开关。这一行只是容器，**不持有存储**——每个 item 自带 `id`、`storageKey`、默认值和自己的 `read` / `write`，builder 在绑定、读取、保存时把它们当成普通 toggle 逐条走一遍。所以「三个按钮合一」不产生新的存储结构，只是把三行画成一行。

胶囊行放不下一整句话，所以单个 item 可以带 `hintKey`：那句话由共享的提示层（`scripts/shared/tooltip.js`）画在胶囊旁边，同一句话也用 `aria-describedby` 挂在输入框上——`content: attr()` 不保证被读屏念出来。提示层挂在 `body` 上、`position: fixed`：卡片是 `overflow: hidden`（圆角要裁行），画在卡片里的提示一要第三行就被切掉。锚点在窗口右侧时提示改为对齐锚点右边缘向左长，否则它会飘到窗口外面去。

## 下拉菜单是自己画的

原生 `<select>` 的弹出列表由系统绘制，在这个全自绘的窗口里是唯一不属于这里的东西。现在换成 `scripts/shared/select-menu.js`：触发器 + 浮动菜单。

**契约不动**：`<select>` 留在原位（`display: none`），继续持有 id、`value` 与 `change`，外壳只负责看与被点。两处不触发事件的写入——宿主直接写 `select.value`、把行禁用——靠实例上的属性影子同步回触发器，否则标签会停在旧值上。

菜单挂在 `document.body` 上并 `position: fixed`：设置内容区自己滚动，流内菜单必被裁掉。代价是它不跟着窗口或弹窗消失，所以关窗口、关弹窗要显式收掉，切换分区时还要扫掉控制器已脱离文档的死菜单。

**无障碍是让出来的**：`<select>` 主动退出无障碍树，触发器 `role="combobox"`、菜单 `role="listbox"`，避免两个控件报同一个值。键盘（↑↓ / Home / End / Enter / Esc）在单测里验过；读屏没有在真机上走过，这一条仍是未确认。

## 通用页分三组

界面 / 搜索 / 启动台。`角落按钮显示` 与 `搜索行为` 各是一行 chips，行名就是这一组开关在管什么：前者三个按钮都在角落里，后者三个开关都在管搜索；启动台的列与行合成一行「布局密度」。行名不能省——省掉之后一行胶囊左边空出一大片，看起来像坏了。分组只改呈现，存储键一个都没动。

缺键不会报错：`t(key)` 把 key 原样返回，界面就会出现 `settingsLaunchpadGridSize` 这样的字。`tests/settings/locales.test.js` 守着三语键集一致，且通用页用到的每个键都有文案。

## 动这里会连带影响谁

- 改快速链接的管理界面，会同时改到「数据」分区里的那一块。
- 更新日志分区由更新日志模块自己注册，这里只提供挂载点。
- 备份的实际打包与还原在平台层，这里只管界面与流程。

## 改坏会出事的

- **写设置只走两个入口**（普通设置、壁纸设置各一个），内容分区不直接碰浏览器存储。绕过入口就等于绕过串行锁，两个窗口同时改会互相覆盖。
- 改动立即生效并落盘，没有「保存」按钮。
- 破坏性操作（清空数据、从备份还原）必须先确认。
- 备份与还原期间挂遮罩并阻止关页面；还原先写暂存库，校验通过才替换正式库。
- 窗口关闭要把焦点还给打开它的按钮。

目前没有测试守着的是后两条：破坏性操作的确认、关闭后的焦点归还。
