# 新标签页外壳

## 这里有什么

把壁纸、时钟、搜索、入口挂到页面上，并决定谁先启动。首屏交接也在这里：一段普通脚本在模块加载之前先把背景画上，等壁纸就绪后再把画面交给它。

## 搜索框的三个状态

**静止是一条光线。** 时钟下方 190×2px 的横线，可点热区 340×30px。搜索框「默认不存在」正是「每次都要点一次」的来源：静止态需要露一个能点的形状，而不是什么都不要。角落那个圆形图标因此降为可选，设置里两档：显示 / 不显示，默认不显示。没有「悬停显示」这一档——悬停显形是整块角落区域的共用行为（刷新、设置、照片信息都用同一套），对搜索按钮来说那一档等于「平时看不见、碰巧飘到角落才出现」，正是光线要消除的发现问题，触屏上也不存在。关掉是加 `disabled`，整块退出布局，指针路过也不会冒出来。

**展开。** 光线就地长成 58px 输入框，时钟缩到 60%（120 → 72），日期跟到 12px（20 → 12）。整组因此变短，输入框随之往上走约 30px——焦点从时间交到输入框上。缩小用 `font-size` 不用 `transform`：`transform` 不改变占位，框就不会上移，只会让时钟周围空出一圈。悬停只提亮不展开：鼠标从 Dock 去右上角会反复穿过屏幕中心。

**位置只有两个，不跟着内容变。** 收起是居中，打开就是上方那个位置——落位发生在框出现的那一刻，之后列表有没有、有几条都不再移动任何东西。让位量（矮窗口最多 200px）是替列表预留的，所以它在框打开时就一起让出去，而不是等列表真的出现。半号时钟留在上方不淡出，Dock 也保持原样。

**开合状态只有一个来源：`<html data-search-open>`。** 不用容器上的类名，是因为第一帧的形状必须由首屏脚本决定：`searchAlwaysVisible` 在 `chrome.storage.sync` 里，那个阶段读不到异步存储，布局层于是把它镜像到 `localStorage`，首屏脚本同步读出来写这个属性。否则开了「始终显示搜索框」的人每个新标签页都会先画一条光线再展开一次。

**收起。** `Esc` 只收回当前页，不回写任何设置。每个新标签页都从光线开始，除非设置里打开「始终显示搜索框」。

旧的 `searchActive` 同步键已删除。它把「搜索框是否显示」当成跨标签页状态持久化，隐藏过一次之后，之后每个新标签页都只剩点角落图标一条路。

## 键盘焦点归浏览器

Chrome 把新标签页的键盘焦点锁在地址栏，页面抢不走。所以打开新标签页那一瞬间，`/`、`⌘K` 和打字都落不到页面上，必须先点一下页面。唯一的绕法是把新标签页重定向到普通扩展页再聚焦，代价是地址栏每次露出 `chrome-extension://<id>/...`——否决。任何「页面级快捷键」因此都只解决第二下。

## 搜索历史与候选

- 历史存 `chrome.storage.local`，上限 50 条，大小写不敏感去重并提到最前，只在真正发出搜索时记录。开关是同步设置 `searchHistoryEnabled`：关掉只停止记录，不清空已有数据。
- 历史会跟着整库备份走（备份导出全部 local 键，没有排除项）。这是有意的：用户导出「整库」时应该拿到它。
- 候选分三类：本机的快速链接命中、最近搜索、引擎联想词。前两类和 Dock、启动台、导入的书签是同一批数据（`store.search()`），不另建索引。
- 面板是一列，没有分组标题、没有行内类型标签：类型只由行首图标说（站点图标 / 放大镜 / 时钟）。分组标题在删掉行内标签后就成了每行重复一遍的同一句话，还各占一行高度。
- 一个查询里每个词都要命中（AND），URL 归一后再比（去 `https://`、`www.`、末尾 `/`），所以 `git hub`、`github com` 都能搜到 GitHub。打分：标题前缀 100 > 标题子串 80 > 标签 60 > 域名 40 > 路径 20，多词相加，同分按标题长度。这套规则在 `store.search()` 里，面板和启动台共用，改一处两边一起变。
- 联想词固定来自 Bing，不跟设置里选的搜索引擎走。原因是 Chrome 没有 API 读用户的默认引擎，跟着走就得猜，猜错等于把输入发给了错的搜索引擎；固定一源也意味着只维护一个解析器。代价是联想词的用词和排序是 Bing 的口味，结果页却可能落在别的引擎上。
- 两个 host、同一端点：`api.bing.com/osjson.aspx` 在前，`cn.bing.com/osjson.aspx` 在后。前者在大陆不可靠。谁答应用谁，整个会话记住——只有第一次查询付超时的代价。只有「这个 host 不行」（网络错误、非 2xx、返回不是那个形状）才换下一个；格式正确但没有联想词是成功，不换，否则每个查不出东西的词都要多打一次请求。两个都挂时静默 30 秒，免得离线用户每次按键都付两次超时。
- 走新标签页自己的 `fetch`：`host_permissions: https://*/*` 已覆盖，扩展页不受 CORS 限制（`layout.js` 下载远程壁纸走的是同一条路）。不绕后台 worker，少一层消息往返，也不受 service worker 被回收影响。
- 失败即缺席：1.5s 超时、断网、返回不是那个形状，都只是少一组，不报错、不留空行。`api.bing.com` 在大陆的可达性未测；不通的表现就是没有联想词。
- 排序按输入状态切换：空输入 = 历史 5 条；有输入 = 快速链接 ≤4 行，然后联想词 ≤5 条，历史 ≤3 条。快速链接在最上面，因为那是用户自己的东西，而联想词只是引擎的猜测。
- 历史在有输入时让位（引擎答了就不显示），因为它和联想词高度重合，同一句话列两次比列短一点更难看；引擎没答案时（离线、超时、这个词它不认识）历史顶回来，面板不会变空。
- 面板里没有「在〈引擎〉搜索 …」这一行。没有高亮行时回车本来就搜输入框原文，多那一行只是把同一件事写第二遍，还占掉一行预算。
- 历史末尾是唯一一个动作行「清除搜索历史」：它进 `↑↓` 序列（键盘用户没有别的入口），回车走已有的确认对话框，所以误按不会直接清空。
- 行内类型对读屏靠 `.sr-only` 文字补回来（图标只是视觉线索）。它必须真的从布局里消失（`position: absolute` + 裁剪），否则会顶在标题前面；代价是它仍在 `textContent` 里，任何按文本比对的地方要自己剔掉。
- 联想词只对取它的那个 query 有效：响应带着自己的 query 回来，对不上或序号过期就丢弃，所以快速打字不会出现上一条的答案盖住这一条。
- 输入法组合期（`compositionstart`–`compositionend`）不发请求，commit 之后补一次。否则中文逐笔输入会被当成十几个无意义的查询发给引擎。
- `↑↓` 全局一行、`↵` 执行、`Tab` 补全（历史与联想词都能补进输入框再编辑）、`Delete` 只删历史。
- 联想词默认开启（同步设置 `searchSuggestions`）。第一次打开面板时最下面一行说明一次「输入的内容会发送给 Bing」并给出关闭入口——显示即记为已见，不再出现；这一行占一行高度，所以它出现时联想词从 5 条降到 4 条。
- 面板高度上限不变（`--search-list-room` 仍是 349）：一列最多 4 + 5 + 3 + 1 行，比上限高，超出的部分靠滚动消化，面板不再为了容纳全部候选而长高，所以框的位置在这次改动里没有重算。
- 溢出时底部渐隐提示「下面还有」，滚到底自动收起；滚动条自绘（6px、无轨道、半透明白，悬停提亮），浏览器默认那根是面板里最吵的东西。渐隐用 `mask-image` 挂在滚动容器本身上——遮罩作用在渲染盒上，行从它下面滚过去，不必多包一层 DOM。框在垂直居中，面板又只能向下展开，居中的一半高度放不下——这是框一出现就让位的原因。整个搜索布局由两个量决定：`--search-list-room`（列表要的地方，323 行高 + 10 间隙 + 16 底边 = 349）和 `--search-box-drop`（框下沿到窗口中线多远，98，跟展开后的时钟、日期、容器内边距绑定）。让位量 = `clamp(0px, list-room + box-drop - 50vh, 200px)`，列表高度上限 = `max(50vh - box-drop, list-room) - 26px`——两者都从同一对量派生，改一处不会和另一处失配。加一行候选就抬 `--search-list-room`；改展开后的时钟大小就重测 `--search-box-drop`。
- 面板 z 序在 Dock 之上。Dock 是 `z-index: 300`，而布局容器因为 `transform` 自成层叠上下文，不提 z 就会看到 Dock 的图标把行切开。Dock 本身不隐藏（它是页面的一部分，不该随搜索消失），所以面板底色必须够实（`--suggestions-bg`，98.5%），否则那排亮色图标会隔着玻璃糊在行中间。
- 输入框左边那个按钮显示**当前引擎自己的标**，换引擎就换标；`default` 不知道浏览器选的是哪家，保留放大镜。标是各家官方轮廓的单色版（simple-icons，CC0；Yandex 的「Я」那个集子里没有，按同一套 24 网格手画），在 `scripts/shared/icons.js` 里一张表。标不带 `width`/`height`，尺寸由 CSS 给：框里 22px、切换面板里 18px——同一个字符串两处用。
- 颜色分两处：框里那个跟 `currentColor`（静止 70% 白，悬停/聚焦纯白），面板里按 `[data-engine]` 给品牌主色。理由是框里只回答"待会儿搜到哪去"，不该比输入框抢眼；面板是"选一个品牌"的地方，颜色在那里才有用。
- 框里从 50% 白提到 70% 白，是因为标是**实心轮廓**：描边放大镜在 50% 下靠线条本身还立得住，一整块实心图形在亮壁纸上会糊成一团浅色。
- 切换面板的每一行多了 16px 图标 + 6px 间距，为了让它还在一行里，内边距从 `12px 20px` 收到 `8px 10px`（11 个引擎原本约 901px，加图标后约 1099px，可用 1141px）。窗口窄于约 1170px 时会折成两行，行内居中——没有为了让它在任何宽度下都不折去动字号，那种"刚好在某一个宽度下才不折"的布局更脆。
- `↑↓` 跨组连续移动，`↵` 执行（没有高亮行时搜输入框原文），`Tab` 把历史或联想词补进输入框再编辑，`Esc` 先关面板再收框，`Delete` 删高亮的历史条目。输入法组合期按回车是提交候选，不会被当成本次搜索。面板内 `mousedown` 一律 `preventDefault`，否则点击行会先触发 blur 把面板清掉。

## 动这里会连带影响谁

- **初始化顺序**：改错会让首屏先闪一下，或者入口比壁纸更早冒出来。
- **首屏脚本**必须保持「普通脚本、跑在模块之前」。改成模块就等于没有首屏。
- 布局层直接开关启动台，改布局会连带它的行为。

## 改坏会出事的

- 首屏之前不做任何阻塞式工作。背景与更新日志都是异步启动，失败也不能连带把首屏清掉。
- 面板只在 `focus` 和 `input` 两处刷新，`focus` 那处必须带 `refreshHistory`。漏掉它时面板渲染的是模块启动时的空数组，历史存在存储里但永远不出现。
- 新增候选行要改的是 `--search-list-room`（一行）。以前这里是“记得同时改两个数”，两处失配就会静默截断——这个坑已经用派生关系填掉了，别再退回手写常数。
- 联想词的端点归 `scripts/domains/search-suggest.js` 一个模块，换源或加源只动那里。别把端点散进 `search.js`：那个文件已经在管开合、键盘、排序和设置同步。
- 联想词请求必须带序号并且只接受属于当前 query 的答案。少了这一步，快速打字时晚到的旧答案会盖住新结果，且只在慢网络上出现。
- 「面板有没有内容」不等于「要不要请求」。删掉搜索行后，打字时面板可能一条都没有（无历史、无匹配链接、答案还没到），若在那里提前返回，请求就永远不会发出去了。现在面板空着也照发，答案到了再画。
- 首次说明是「每个安装一次、本页常驻」，不是「每次渲染」。按渲染判断时，引擎答案到达触发的那次重绘会把它抹掉，用户只看到一闪。
- 渲染里不许无条件地再排一次取词。答案已在手（`_suggestQuery` 就是当前 query）时再排，就是「渲染 → 请求 → 渲染」的自激循环：面板每 120ms 重画一次，而每次重画都会 `_setActive(-1)`，于是 `↑↓` 高亮刚设上就被抹掉，`Tab` 补全也跟着失效。单测看不出来，只有真浏览器里按方向键才暴露。
- 真实链路只有装进 Chromium 跑新标签页才知道通不通（`harness/e2e-extension.mjs`）：静态 harness 剥掉了脚本，量得到布局、量不到请求。
- 框的位置不能挂在「面板是否出现」上。挂在面板上时先出现的是框、框在中间，等历史读完整体跳上去；而历史读取是异步的，跳的时机也不可控。
- `clamp()` 里的算式要自带内层 `calc()`。省掉时浏览器解析通过、计算时整条 `transform` 作废，布局静默失效，不报错也看不出为什么。
- 时钟缩小必须走 `font-size`。改成 `transform: scale()` 时占位不变，输入框不会跟着上移，缩小就只剩「周围空一圈」的效果。
- 既然缩小在动 `font-size`，时钟上就不能挂模糊。带 `filter` 的元素要先渲染成纹理再跑高斯模糊，而字号每帧都在变，纹理和两次模糊就每帧重做。曾挂过两层 `drop-shadow`（60px / 120px 半径）：配对实测每次展开的超预算帧 4 → 45，每帧中位 8.95 → 10.94ms，而它只买到收起状态多一圈最大差 7/255 的光晕、展开状态逐像素毫无区别。要发光用 `text-shadow`——它跟着字形一起栅格化，不另起一层。
- 搜索框的开合只有一个来源 `<html data-search-open>`。再在容器上加一个类名管理同一个状态，两边不同步时就变成首帧闪烁。
- `searchAlwaysVisible` 改动必须同时更新 localStorage 镜像，否则下一张新标签页会画错形状。
- 页面是一次性的：要跨标签页保留的状态必须进存储。
- 语言、主题变化要就地生效，不要求刷新页面。
