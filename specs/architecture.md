# Aura Tab — 架构总览

## 一分钟版本

装进浏览器后，Aura Tab 是三份各自运行的代码，互相只能发消息，不能直接调用。

- **新标签页**（`newtab.html`）：全部界面与业务。每开一个标签页就从零启动一次，关掉就全没了。
- **后台服务**（`background-worker.js`）：没有界面的进程，浏览器空闲一会儿就可能杀掉它，有事件再唤醒。它负责定时换壁纸、代替页面抓网站图标。
- **隐藏页面**（`favicon-offscreen.html`）：看不见的网页，只借它的解析能力——后台进程没有 DOM。

分开的理由：页面关了，定时换壁纸还得继续；在页面里跨域抓图标会被浏览器拦；后台进程解析网页需要 DOM。

由此得出一条最硬的约束：**没有「内存里存一下」这条路**。页面每次冷启动、后台随时被杀，要跨次保留的东西必须进存储。首屏快照、sync 配额、缓存淘汰都是这一条的后果。

## 依赖方向

`domains/ → platform/ → shared/`，只准往下引用。`domains/` 是功能本体，`platform/` 封装浏览器能力，`shared/` 是纯工具。

### 已知的越层引用（已决定：暂不处理）

这些都是「能跑、但方向不对」，动到相关代码时可以顺手拆：

| 引用 | 相当于 | 状态 |
|---|---|---|
| `platform/settings-contract` → 壁纸默认值表 | 底层引用上层 | 暂不处理 |
| 页面布局 → 启动台的开合 | 模块直连模块 | 暂不处理 |
| 书签导入 → 快速链接存储 | 模块直连模块 | 未定 |
| 照片查看器 → 壁纸素材库 | 模块直连模块 | 暂不处理 |
| 设置面板 → 快速链接的配置与组件 | 模块直连模块 | 暂不处理 |
| 设置窗口 ⇄ 更新日志 | 唯一的双向引用 | 暂不处理 |

新增依赖时不要把它们当惯例。

## 存储分工

| 存哪 | 放什么 | 为什么 |
|---|---|---|
| `chrome.storage.sync` | 设置、快速链接 | 要在用户自己的设备间同步；受约 100KB 总量限制 |
| `chrome.storage.local` | 首屏快照、各类索引、已读版本 | 本机态，不值得同步 |
| IndexedDB | 图片、图标的二进制 | `chrome.storage` 放不下大对象 |
| Cache Storage | 壁纸图片缓存 | 交给浏览器按容量淘汰 |

## 改坏会出事的

这些条目描述代码现在的行为，不是覆盖率清单——哪条被测试守着，以 `tests/` 为准。

- **设置只有两个写入口**（普通设置、壁纸设置各一个），全部在同一把命名锁上串行。绕过入口改 `chrome.storage` 就等于绕过锁，两个窗口同时改会互相覆盖。
- **大对象不进 `chrome.storage`**；图片、二进制只进 IndexedDB 或 Cache Storage。
- **跨上下文传二进制必须转成数字数组**，直接传 `ArrayBuffer` 在部分浏览器版本会丢数据。
- **界面文案只有一个家**：`scripts/platform/locales/`；`_locales/` 只保留 manifest 需要的键。
- **sync 写满就快速失败**，不做部分写入。
- **页面脚本必须是外链文件**（CSP 限制），HTML 里不允许内联事件处理器。

## 构建与发布

没有构建步骤，源码即产物。测试是 Vitest + jsdom、用 mock 替换浏览器接口，没有真实浏览器的端到端。发布由 `package_extension.sh` 按白名单打 zip。

一处遗留：`chrome.storage.session` 里写了一份壁纸外观镜像，目前没有读者。
